# Requirements Document

## Introduction

MCP Proxy Gateway（MCP 桥接代理网关）是一个通用的 MCP（Model Context Protocol）聚合与代理网关服务。系统使用 Go 语言开发后端，前端管理界面基于开源模板 TailAdmin Vue（Vue3 + Vite + TypeScript + Tailwind CSS 的后台管理仪表盘模板）构建，并由 Go 进程直接代理前端静态页面访问（无需 Nginx）。

系统的核心目标是：对接市面上各种连接方式的 MCP 服务，将它们提供的工具进行统一聚合管理（增删查改、启用停用、排序、自动同步、缓存），支持对接入 MCP 的工具进行别名重命名、重新描述和屏蔽过滤（规则绑定在 MCP 上，与具体工具解耦，支持名称或正则匹配、多规则、单条启停），并对外提供多种形式的聚合 MCP API 能力（智能模式与全量工具模式），供其他 AI 服务调用。系统还提供 API Key 管理与精细化访问控制、多维度统计排行，以及小智 AI 远程 MCP 接入点对接等扩展能力。

系统通过环境变量配置 PostgreSQL 与 Redis 连接，通过 YAML 文件保存常规配置，挂载 data 目录持久化数据，支持 Docker 容器化一键部署，并通过 GitHub Action 实现自动化打包与 Docker 镜像远程发布。

## Glossary

- **网关系统（Gateway_System）**：MCP Proxy Gateway 整体系统，作为对内管理与对外服务的统一载体。
- **MCP**：Model Context Protocol，模型上下文协议，定义 AI 模型与工具之间交互的协议。
- **上游 MCP 服务（Upstream_MCP）**：被网关系统接入并代理的外部 MCP 服务实例。
- **传输适配层（Transport_Adapter）**：负责屏蔽不同 MCP 连接方式差异的抽象组件，支持 stdio、SSE、Streamable-HTTP、WebSocket 等传输类型。
- **MCP 连接管理器（MCP_Manager）**：负责上游 MCP 服务的增删查改、启用停用、排序与连接生命周期管理的组件。
- **工具同步服务（Sync_Service）**：负责从上游 MCP 拉取工具列表并更新缓存的组件。
- **工具缓存（Tool_Cache）**：基于 Redis 与数据库存储的上游 MCP 工具列表缓存。
- **规则引擎（Rule_Engine）**：负责对工具应用别名、描述重写与屏蔽过滤规则的组件。
- **别名规则（Alias_Rule）**：绑定在某个上游 MCP 上、用于重命名工具名称或重写工具描述的规则。
- **屏蔽规则（Filter_Rule）**：绑定在某个上游 MCP 或 API Key 上、用于屏蔽过滤工具的规则。
- **聚合服务（Aggregation_Service）**：负责将多个上游 MCP 工具合并为统一工具集合的组件。
- **MCP API 服务（MCP_API_Service）**：对外提供聚合后 MCP 能力的服务端点。
- **智能模式（Smart_Mode）**：对外仅暴露少量网关工具、按需发现具体工具的工作模式。
- **全量工具模式（Full_Mode）**：对外一次性暴露全部聚合工具的工作模式。
- **网关工具（Gateway_Tool）**：智能模式下用于工具发现与调用的少量代理工具（如列出工具、调用工具）。
- **API Key 管理器（ApiKey_Manager）**：负责 API Key 的创建、删除、过滤规则与访问控制的组件。
- **API Key（Api_Key）**：外部 AI 服务调用网关 MCP API 时使用的访问凭证。
- **统计服务（Statistics_Service）**：负责按 MCP、工具、API Key 等维度采集调用数据并生成排行与统计的组件。
- **小智接入服务（XiaoZhi_Connector）**：通过 WebSocket 连接小智 AI 远程 MCP 接入点、将聚合后 MCP 能力提供给小智的组件。
- **认证服务（Auth_Service）**：负责管理员注册、登录与会话管理的组件。
- **配置管理器（Config_Manager）**：负责读取与持久化 YAML 配置及环境变量的组件。
- **静态资源服务（Static_Server）**：由 Go 进程提供前端静态页面访问的组件。
- **TailAdmin 模板（TailAdmin_Template）**：开源的 Vue3 + Vite + TypeScript + Tailwind CSS 后台管理仪表盘模板（vue-tailwind-admin-dashboard），作为前端管理界面的基础模板与视觉风格来源。
- **Tailwind CSS（Tailwind_CSS）**：基于原子化工具类（utility classes）的 CSS 框架，作为前端管理界面的样式基础。
- **健康检查服务（Health_Service）**：负责暴露系统与连接健康状态的组件。
- **审计日志服务（Audit_Service）**：负责记录管理操作与关键事件的组件。
- **快捷模板（Quick_Template）**：用于快速添加常用第三方 MCP 服务的预设配置模板。
- **模板市场（Template_Market）**：提供分类化、可检索的内置快捷模板集合，供管理员快速浏览并接入常用第三方 MCP 服务的组件。
- **快捷模板分类（Template_Category）**：用于对快捷模板进行归类的维度（如搜索、开发工具、数据库与存储等）。
- **管理员（Administrator）**：系统的单一管理用户。

## Requirements

### Requirement 1: 管理员认证与单用户管理

**User Story:** 作为系统管理员，我希望在首次使用时注册管理员账号并在之后登录系统，以便安全地管理网关配置。

#### Acceptance Criteria

1. 当系统首次启动且 YAML 配置文件中不存在管理员账号时，THE 认证服务 SHALL 进入首次初始化状态并提供管理员注册入口。
2. 当管理员提交的注册用户名长度为 3 至 32 个字符且密码长度为 6 至 128 个字符时，THE 认证服务 SHALL 将该管理员账号以加盐哈希形式写入 YAML 配置文件并完成初始化。
3. 如果在系统已存在管理员账号的情况下收到新的管理员注册请求，THEN THE 认证服务 SHALL 拒绝该注册请求、保持单用户管理并保留现有管理员账号不变。
4. 当管理员提交的用户名与密码与已存储的加盐哈希凭证匹配时，THE 认证服务 SHALL 创建有效期等于配置的会话超时时长（默认 3600 秒，取值范围 300 至 86400 秒）的有效会话并返回访问令牌。
5. 如果管理员提交的用户名或密码与已存储的加盐哈希凭证不匹配，THEN THE 认证服务 SHALL 拒绝登录、不创建会话并返回鉴权失败错误。
6. 当请求访问受保护的管理接口且其访问令牌缺失、无效或已过期时，THE 认证服务 SHALL 拒绝该请求并返回未授权错误。
7. 当管理员令牌的存活时长超过配置的会话超时时长（默认 3600 秒，取值范围 300 至 86400 秒）时，THE 认证服务 SHALL 使该令牌失效并要求重新登录。
8. 当管理员请求修改自身密码、提供的当前密码与已存储的加盐哈希凭证匹配且新密码长度为 6 至 128 个字符时，THE 认证服务 SHALL 更新密码哈希并写入 YAML 配置文件。
9. 如果管理员提交的注册用户名长度不在 3 至 32 个字符范围内，或密码长度不在 6 至 128 个字符范围内，THEN THE 认证服务 SHALL 拒绝该注册请求、不写入任何账号并返回指示输入校验失败的错误。
10. 如果管理员修改密码时提供的当前密码与已存储的加盐哈希凭证不匹配，或新密码长度不在 6 至 128 个字符范围内，THEN THE 认证服务 SHALL 拒绝该修改请求、保留原密码哈希不变并返回指示密码修改失败的错误。

### Requirement 2: 上游 MCP 服务的增删查改

**User Story:** 作为管理员，我希望对上游 MCP 服务进行增删查改，以便统一管理被代理的 MCP 服务。

#### Acceptance Criteria

1. 当管理员提交新的上游 MCP 服务配置（包含长度为 1 至 100 个字符的名称、传输类型与连接参数）时，THE MCP 连接管理器 SHALL 持久化该配置并返回创建成功结果。
2. 如果管理员提交的上游 MCP 配置缺少必填字段、名称长度不在 1 至 100 个字符范围内或字段格式无效，THEN THE MCP 连接管理器 SHALL 拒绝创建、不持久化任何配置变更并返回标识每个无效字段的校验错误。
3. 当管理员请求查询上游 MCP 服务列表时，THE MCP 连接管理器 SHALL 返回所有已配置的上游 MCP 服务及其当前连接状态。
4. 当管理员请求更新某个已存在的上游 MCP 服务的配置时，THE MCP 连接管理器 SHALL 保存更新后的配置并按新配置重建对应连接。
5. 当管理员请求删除某个已存在的上游 MCP 服务时，THE MCP 连接管理器 SHALL 关闭对应连接、删除该服务及其关联的工具缓存与规则并返回删除成功结果。
6. 如果管理员请求更新或删除的上游 MCP 服务标识不存在，THEN THE MCP 连接管理器 SHALL 拒绝该操作、不持久化任何变更并返回资源不存在错误。
7. 如果管理员提交的创建或更新请求中的服务名称与其他已存在的上游 MCP 服务名称重复，THEN THE MCP 连接管理器 SHALL 拒绝该操作、不持久化任何配置变更并返回名称冲突错误。
8. 当管理员请求查询上游 MCP 服务列表且当前不存在任何已配置的上游 MCP 服务时，THE MCP 连接管理器 SHALL 返回空列表而非错误。

### Requirement 3: 上游 MCP 服务的启用、停用与排序

**User Story:** 作为管理员，我希望启用、停用和排序上游 MCP 服务，以便控制哪些 MCP 参与聚合以及它们的展示与匹配顺序。

#### Acceptance Criteria

1. 当管理员启用某个上游 MCP 服务时，THE MCP 连接管理器 SHALL 将该服务标记为启用状态，并使该服务的工具在该次启用之后接收的聚合请求中被纳入聚合范围。
2. 当管理员停用某个上游 MCP 服务时，THE MCP 连接管理器 SHALL 将该服务标记为停用状态，并使该服务的工具在该次停用之后接收的聚合请求中被排除在聚合范围之外。
3. 在某个上游 MCP 服务处于停用状态时，THE 聚合服务 SHALL 在对外暴露的聚合工具集合中不包含该服务的任何工具。
4. 当管理员提交上游 MCP 服务的新排序顺序时，THE MCP 连接管理器 SHALL 持久化该排序，并在列表查询结果与聚合工具集合中均按该排序由前到后返回各服务及其工具。
5. 如果管理员提交的排序顺序包含未注册的服务标识、缺失任一已注册服务的标识、或包含重复的服务标识，THEN THE MCP 连接管理器 SHALL 拒绝该排序请求、保持当前已持久化的排序状态不变，并向调用方返回指示排序无效原因（未注册标识、缺失标识或重复标识）的错误。
6. 如果两个或多个处于启用状态的上游 MCP 服务暴露相同的工具名称，THEN THE 聚合服务 SHALL 按已配置的排序顺序由前到后确定优先级，使排序在前的服务保留其原始工具名称、排序在后的服务的同名工具被赋予可区分的标记，并确保对外暴露的聚合工具集合中所有工具名称唯一。

### Requirement 4: MCP 传输方式适配

**User Story:** 作为管理员，我希望网关支持市面上各种连接方式的 MCP 服务，以便接入不同类型的上游 MCP。

#### Acceptance Criteria

1. THE 传输适配层 SHALL 能够与 stdio 传输类型的上游 MCP 建立连接并完成 MCP 协议初始化，从而收发该上游 MCP 的工具列表与工具调用消息。
2. THE 传输适配层 SHALL 能够与 SSE（Server-Sent Events）传输类型的上游 MCP 建立连接并完成 MCP 协议初始化，从而收发该上游 MCP 的工具列表与工具调用消息。
3. THE 传输适配层 SHALL 能够与 Streamable-HTTP 传输类型的上游 MCP 建立连接并完成 MCP 协议初始化，从而收发该上游 MCP 的工具列表与工具调用消息。
4. THE 传输适配层 SHALL 能够与 WebSocket 传输类型的上游 MCP 建立连接并完成 MCP 协议初始化，从而收发该上游 MCP 的工具列表与工具调用消息。
5. 当管理员配置上游 MCP 服务时，THE 传输适配层 SHALL 根据所选传输类型校验该类型对应的全部必填连接参数是否齐备且格式合法。
6. 如果上游 MCP 服务声明的传输类型不属于受支持的传输类型集合（stdio、SSE、Streamable-HTTP 与 WebSocket），THEN THE 传输适配层 SHALL 拒绝建立连接并返回指示传输类型不受支持的错误。
7. WHERE 上游 MCP 连接需要鉴权凭证，THE 传输适配层 SHALL 在建立连接时携带所配置的鉴权凭证。
8. 如果管理员所配置上游 MCP 服务缺少所选传输类型要求的必填连接参数或参数格式非法，THEN THE 传输适配层 SHALL 拒绝建立连接、不将该不完整配置生效为可用连接，并返回指示具体缺失或格式非法连接参数的校验错误。
9. 如果传输适配层为某个上游 MCP 建立连接的过程在配置的连接建立超时时长（默认 30 秒）内未完成 MCP 协议初始化，THEN THE 传输适配层 SHALL 中止本次连接尝试并将该连接标记为建立失败。

### Requirement 5: 上游 MCP 连接重试与退避

**User Story:** 作为管理员，我希望网关在与上游 MCP 连接异常时自动重试，以便在网络波动后自动恢复连接。

#### Acceptance Criteria

1. 如果与某个上游 MCP 服务的连接建立失败，THEN THE MCP 连接管理器 SHALL 按指数退避策略重试连接，其初始退避间隔默认为 1 秒（可配置范围 1 至 60 秒），且每次重试后将上一次退避间隔乘以倍数 2 得到下一次退避间隔。
2. 如果某个已建立的上游 MCP 连接在运行期间断开，THEN THE MCP 连接管理器 SHALL 采用与连接建立失败相同的指数退避策略（初始退避间隔默认 1 秒、可配置范围 1 至 60 秒、倍数 2）重试该连接。
3. THE MCP 连接管理器 SHALL 将连接重试的退避间隔上限限制为配置的最大退避时长（默认 60 秒，可配置范围 1 至 3600 秒），使任何单次重试的退避间隔均不超过该上限，并在状态查询中体现当前生效的最大退避时长。
4. WHILE 某个上游 MCP 连接处于断开状态，THE MCP 连接管理器 SHALL 将该连接的状态标记为不可用，并在状态查询中返回该连接的不可用状态及最近一次连接失败的原因。
5. 当断开的上游 MCP 连接重试成功时，THE MCP 连接管理器 SHALL 将该连接状态恢复为可用、将该连接的连续失败次数重置为 0 并继续提供其工具。
6. 如果某个上游 MCP 连接的连续失败次数达到配置的阈值（默认 5 次，可配置范围 1 至 100 次），THEN THE MCP 连接管理器 SHALL 记录告警事件并暂停该连接的自动重试，直至该上游 MCP 在需求 7 所配置的自动同步调度周期再次触发或管理员手动发起重连。

### Requirement 6: 工具列表缓存

**User Story:** 作为管理员，我希望网关缓存上游 MCP 的工具列表，以便聚合查询与调用时避免性能问题。

#### Acceptance Criteria

1. 当工具同步服务从某个上游 MCP 获取到工具列表时，THE 工具缓存 SHALL 以该次获取的完整工具列表替换该上游 MCP 先前已缓存的工具列表，并持久化该工具列表及其更新时间戳。
2. 当聚合服务需要工具列表时，THE 聚合服务 SHALL 从工具缓存读取该上游 MCP 最近一次持久化的工具列表，且不向上游 MCP 发起实时请求。
3. 如果工具缓存中不存在某个已启用上游 MCP 的工具列表，THEN THE 工具同步服务 SHALL 触发一次该上游 MCP 的工具列表拉取。
4. 当管理员请求手动刷新某个上游 MCP 的工具列表且该次拉取成功时，THE 工具同步服务 SHALL 不等待下一个自动同步周期，以该次拉取的最新工具列表完整替换并更新工具缓存。
5. 如果管理员请求手动刷新某个上游 MCP 的工具列表但该次拉取失败，THEN THE 工具同步服务 SHALL 保留该上游 MCP 最近一次成功缓存的工具列表，并向管理员返回指示刷新失败的错误。
6. 当某个上游 MCP 服务被删除时，THE 工具缓存 SHALL 删除该上游 MCP 对应的缓存工具列表。

### Requirement 7: 工具自动同步与同步调度配置

**User Story:** 作为管理员，我希望开关并配置工具自动同步，以便工具列表保持最新且同步频率可控。

#### Acceptance Criteria

1. WHERE 某个上游 MCP 服务开启了自动同步，WHEN 已配置的 cron 调度到达一个触发时间点，THE 工具同步服务 SHALL 对该上游 MCP 触发一次工具列表拉取。
2. WHERE 某个上游 MCP 服务关闭了自动同步，THE 工具同步服务 SHALL 不对该上游 MCP 执行周期性同步。
3. WHEN 管理员在系统设置页面提交同步 cron 表达式时，THE 配置管理器 SHALL 校验该表达式是否为标准 cron 格式且每个字段的取值均落在其合法范围内，并仅在校验通过时将该表达式持久化到配置。
4. IF 管理员提交的 cron 表达式不是标准 cron 格式或存在字段取值超出合法范围，THEN THE 配置管理器 SHALL 拒绝保存并返回 cron 格式错误。
5. IF 某次自动同步从上游 MCP 拉取工具列表失败，或在配置的同步超时时间（默认 30 秒，可配置范围为 5 至 300 秒）内未完成拉取，THEN THE 工具同步服务 SHALL 保留上一次成功的缓存工具列表并记录包含失败原因的同步失败事件。
6. WHEN 同步 cron 配置被更新并通过合法性校验时，THE 工具同步服务 SHALL 取消旧调度下尚未触发的后续同步任务。
7. WHEN 同步 cron 配置被更新并通过合法性校验时，THE 工具同步服务 SHALL 在不重启服务的情况下按新的调度周期执行后续同步。
8. IF 某个上游 MCP 的上一次同步尚未完成而该上游 MCP 的新同步触发时间点到达，THEN THE 工具同步服务 SHALL 跳过本次该上游 MCP 的同步触发。

### Requirement 8: 工具别名重命名与描述重写

**User Story:** 作为管理员，我希望对接入 MCP 内的工具进行别名重命名和重新描述，以便自定义对外暴露的工具名称与说明。

#### Acceptance Criteria

1. 当管理员创建别名规则（包含长度为 1 至 200 个字符的匹配模式、是否启用正则匹配标志、作用范围，以及目标名称与目标描述中的至少一项，其中目标名称长度为 1 至 100 个字符、目标描述长度不超过 1024 个字符）时，THE 规则引擎 SHALL 持久化该独立规则，并支持将其作用于全部上游 MCP 或指定多个上游 MCP。
2. WHERE 某条匹配某个工具的别名规则定义了目标名称，WHEN 聚合服务输出该工具时，THE 规则引擎 SHALL 使用该别名规则定义的目标名称替换该工具对外暴露的名称。
3. WHERE 某条匹配某个工具的别名规则定义了目标描述，WHEN 聚合服务输出该工具时，THE 规则引擎 SHALL 使用该别名规则定义的目标描述替换该工具对外暴露的描述。
4. WHILE 某条别名规则作用范围内的上游 MCP 当前不存在与之匹配的工具，THE 规则引擎 SHALL 保留该规则且不产生错误。
5. 当多条别名规则匹配同一个工具时，THE 规则引擎 SHALL 按规则的排序顺序仅应用第一条匹配的别名规则并忽略其余匹配的别名规则。
6. 如果某条别名规则的目标名称与同一聚合范围内的其他工具名称冲突，THEN THE 规则引擎 SHALL 记录冲突事件并为该冲突名称追加可区分的后缀，确保该聚合范围内对外暴露的工具名称唯一。
7. WHERE 某条别名规则开启了正则匹配，THE 规则引擎 SHALL 将该规则的匹配模式作为正则表达式对工具原始名称进行完整匹配（full match）。
8. WHERE 某条别名规则关闭了正则匹配，THE 规则引擎 SHALL 将该规则的匹配模式与工具原始名称进行区分大小写的精确相等比较。
9. 如果某条别名规则开启了正则匹配且匹配模式不是合法的正则表达式，或匹配模式为空或长度超过 200 个字符，或目标名称与目标描述均未提供，THEN THE 规则引擎 SHALL 拒绝保存该规则、不持久化任何数据并返回指示校验失败的错误。

### Requirement 9: 工具屏蔽过滤规则

**User Story:** 作为管理员，我希望独立维护屏蔽过滤规则，并按需作用于全部或多个指定上游 MCP，以便在工具经常变化时规则仍然稳定且与具体工具解耦。

#### Acceptance Criteria

1. 当管理员创建屏蔽规则（包含长度为 1 到 200 个字符的匹配模式、是否启用正则匹配标志、启用状态与作用范围）时，THE 规则引擎 SHALL 持久化该独立规则，并支持将其作用于全部上游 MCP 或指定多个上游 MCP。
2. THE 规则引擎 SHALL 支持维护最多 100 条 MCP 级屏蔽规则。
3. 当某条屏蔽规则处于启用状态且匹配某个工具时，THE 聚合服务 SHALL 将该工具排除在对外暴露的聚合工具集合之外。
4. WHILE 某条屏蔽规则处于停用状态，THE 规则引擎 SHALL 在匹配过程中忽略该规则。
5. WHERE 某条屏蔽规则开启了正则匹配，THE 规则引擎 SHALL 将该规则的匹配模式作为正则表达式对工具原始名称进行完整匹配（full match）。
6. WHERE 某条屏蔽规则关闭了正则匹配，THE 规则引擎 SHALL 将该规则的匹配模式与工具原始名称进行区分大小写的精确相等比较。
7. 如果某条屏蔽规则开启了正则匹配且匹配模式不是合法的正则表达式，THEN THE 规则引擎 SHALL 拒绝保存该规则、不持久化任何数据并返回指示正则表达式无效的错误。
8. 如果某条屏蔽规则的匹配模式为空或长度超过 200 个字符，THEN THE 规则引擎 SHALL 拒绝保存该规则、不持久化任何数据并返回指示匹配模式长度无效的校验错误。
9. 如果创建屏蔽规则会使 MCP 级屏蔽规则总数超过 100 条，THEN THE 规则引擎 SHALL 拒绝保存该规则、不持久化任何数据并返回指示规则数量超过上限的错误。
10. 在某条屏蔽规则作用范围内的上游 MCP 当前不存在与之匹配的工具时，THE 规则引擎 SHALL 保留该规则且不产生错误。
11. 当管理员启用或停用某条屏蔽规则时，THE 规则引擎 SHALL 更新该规则的启用状态，并对该次更新之后接收的聚合请求按更新后的启用状态进行匹配。

### Requirement 10: 工具聚合服务

**User Story:** 作为管理员，我希望网关将管理的多个 MCP 工具聚合为统一工具集合，以便对外提供统一的 MCP 能力。

#### Acceptance Criteria

1. THE 聚合服务 SHALL 从工具缓存读取所有处于启用状态的上游 MCP 的工具列表，并按已配置的上游 MCP 排序顺序由前到后合并为统一的聚合工具集合。
2. 当聚合服务构建聚合工具集合时，THE 聚合服务 SHALL 先应用屏蔽规则排除被屏蔽的工具，再应用别名与描述重写规则。
3. 当外部 AI 服务请求调用某个存在于当前聚合工具集合中的聚合工具时，THE 聚合服务 SHALL 将该调用连同其原始调用参数路由到该工具所属的上游 MCP，并将上游 MCP 返回的执行结果（无论为成功结果还是上游报告的错误结果）原样返回给调用方。
4. 如果外部 AI 服务请求调用的聚合工具不存在于当前聚合工具集合中，THEN THE 聚合服务 SHALL 不向任何上游 MCP 转发该调用并返回工具不存在错误。
5. 如果被调用工具所属的上游 MCP 连接不可用，THEN THE 聚合服务 SHALL 不向该上游 MCP 转发该调用并返回上游服务不可用错误。
6. 当聚合工具被调用且该工具配置了别名时，THE 聚合服务 SHALL 将对外别名映射回上游 MCP 的原始工具名称后再转发调用。
7. 当聚合服务构建聚合工具集合且当前不存在任何处于启用状态的上游 MCP，或所有工具均被屏蔽规则过滤时，THE 聚合服务 SHALL 返回空的聚合工具集合而非错误。
8. 如果被调用工具所属的上游 MCP 在配置的上游调用超时时长（默认 30 秒，取值范围 1 至 600 秒）内未返回执行结果，THEN THE 聚合服务 SHALL 中止本次调用、不返回部分结果并返回指示上游调用超时的错误。

### Requirement 11: 对外 MCP API 服务与智能模式 / 全量模式

**User Story:** 作为外部 AI 服务，我希望通过网关的 MCP API 调用聚合后的工具，并可选择智能模式以节省上下文窗口，以便高效使用聚合能力。

#### Acceptance Criteria

1. THE MCP API 服务 SHALL 以 MCP 协议对外暴露聚合后的工具能力供外部 AI 服务调用。
2. WHERE 对外 MCP API 配置为全量工具模式，THE MCP API 服务 SHALL 一次性向外部 AI 服务暴露全部聚合工具的定义。
3. WHERE 对外 MCP API 配置为智能模式，THE MCP API 服务 SHALL 仅向外部 AI 服务暴露少量用于工具发现与工具调用的网关工具（gateway tools），而不一次性暴露全部聚合工具定义。
4. 在智能模式下，WHEN 外部 AI 服务调用工具发现网关工具时，THE MCP API 服务 SHALL 返回名称或描述中包含查询关键字的聚合工具列表，返回数量默认为 50 条且可在 1 至 200 条范围内配置。
5. 在智能模式下，IF 外部 AI 服务调用工具发现网关工具且当前可见聚合工具集合中不存在名称或描述包含查询关键字的聚合工具，THEN THE MCP API 服务 SHALL 返回空列表而非返回错误。
6. 在智能模式下，WHEN 外部 AI 服务通过网关工具请求调用某个存在于当前可见聚合工具集合中的具体聚合工具时，THE MCP API 服务 SHALL 将该调用路由到对应聚合工具并返回执行结果。
7. 在智能模式下，IF 外部 AI 服务通过网关工具请求调用的工具不存在于当前可见聚合工具集合中，THEN THE MCP API 服务 SHALL 拒绝该调用、不对任何聚合工具发起调用，并返回指示该工具不存在的错误。
8. THE MCP API 服务 SHALL 支持以多种 MCP 传输形式（至少包含 SSE、Streamable-HTTP 与 WebSocket）对外提供聚合 MCP 能力。
9. WHEN 外部 AI 服务请求对外 MCP API 时，THE MCP API 服务 SHALL 在暴露任何聚合工具能力之前校验请求所携带的 API Key 有效性。

### Requirement 12: API Key 管理

**User Story:** 作为管理员，我希望管理对外访问的 API Key，以便控制哪些外部服务可以调用聚合 MCP 能力。

#### Acceptance Criteria

1. 当管理员请求创建新的 API Key 且提供的名称长度为 1 至 100 个字符时，THE API Key 管理器 SHALL 生成在全局范围内唯一的 API Key，将其名称、创建时间与启用状态持久化为元数据，并将该 API Key 的初始启用状态设置为启用。
2. 当管理员请求删除某个 API Key 时，THE API Key 管理器 SHALL 删除该 API Key，使得后续携带该 API Key 的对外 MCP API 请求被拒绝并返回鉴权失败错误。
3. 当管理员请求查询 API Key 列表时，THE API Key 管理器 SHALL 返回所有 API Key 的元数据（包含名称、创建时间与启用状态），且不返回任何 API Key 的完整明文密钥。
4. 当管理员停用某个 API Key 时，THE API Key 管理器 SHALL 将该 API Key 标记为停用状态，使得后续携带该 API Key 的对外 MCP API 请求被拒绝并返回鉴权失败错误。
5. 如果对外 MCP API 请求携带的 API Key 不存在、处于停用状态或已超过有效期，THEN THE MCP API 服务 SHALL 拒绝该请求、不将其路由至任何后端 MCP 能力，并返回鉴权失败错误。
6. WHERE 某个 API Key 配置了有效期，WHEN 当前时间超过该 API Key 的有效期，THE API Key 管理器 SHALL 将该 API Key 标记为失效状态，使得后续携带该 API Key 的对外 MCP API 请求被拒绝并返回鉴权失败错误。
7. 如果管理员请求删除或停用的 API Key 不存在，THEN THE API Key 管理器 SHALL 拒绝该操作并返回指示目标 API Key 不存在的错误。
8. 如果管理员请求创建 API Key 时提供的名称长度小于 1 个字符或大于 100 个字符，THEN THE API Key 管理器 SHALL 拒绝该创建请求、不持久化任何元数据，并返回指示名称长度无效的错误。
9. 当管理员请求查询 API Key 列表且系统中不存在任何 API Key 时，THE API Key 管理器 SHALL 返回空列表。

### Requirement 13: API Key 级别的工具过滤与访问控制

**User Story:** 作为管理员，我希望针对不同的 API Key 进一步过滤聚合后的工具并控制访问，以便实现更精细化的权限管理。

#### Acceptance Criteria

1. 当管理员在某个 API Key 上创建屏蔽过滤规则（包含长度为 1 至 200 个字符的匹配模式、是否启用正则匹配标志与启用状态）时，THE API Key 管理器 SHALL 持久化该规则并将其绑定到该 API Key。
2. THE API Key 管理器 SHALL 支持在同一个 API Key 上维护最多 100 条屏蔽过滤规则。
3. 如果在某个 API Key 上创建屏蔽过滤规则会使该 API Key 的规则数量超过 100 条，THEN THE API Key 管理器 SHALL 拒绝保存该规则、不持久化任何数据并返回指示规则数量超过上限的错误。
4. 如果某条 API Key 屏蔽过滤规则开启了正则匹配且匹配模式不是合法的正则表达式，或匹配模式为空或长度超过 200 个字符，THEN THE API Key 管理器 SHALL 拒绝保存该规则、不持久化任何数据并返回指示匹配模式无效的校验错误。
5. WHERE 某条 API Key 屏蔽过滤规则开启了正则匹配，THE 规则引擎 SHALL 将该规则的匹配模式作为正则表达式对工具原始名称进行完整匹配（full match）。
6. WHERE 某条 API Key 屏蔽过滤规则关闭了正则匹配，THE 规则引擎 SHALL 将该规则的匹配模式与工具原始名称进行区分大小写的精确相等比较。
7. 当使用某个 API Key 请求聚合工具集合时，THE 规则引擎 SHALL 在完成工具聚合并应用上游 MCP 级规则之后，于该 API Key 的可见工具集合中排除被该 API Key 启用的屏蔽规则匹配的工具。
8. 当管理员启用或停用某条 API Key 屏蔽过滤规则时，THE 规则引擎 SHALL 更新该规则状态，并对该次更新之后接收的请求按更新后的启用状态进行匹配。
9. WHERE 某个 API Key 配置了访问控制来源限制（IP 或 CIDR 白名单），THE MCP API 服务 SHALL 仅允许来源地址落在该白名单内的请求使用该 API Key。
10. 如果某个使用该 API Key 的请求来源地址不在其配置的 IP 或 CIDR 白名单内，THEN THE MCP API 服务 SHALL 拒绝该请求并返回访问被拒绝错误。

### Requirement 14: 快捷模板市场与第三方 MCP 服务快速接入

**User Story:** 作为管理员，我希望通过一个分类化、可检索的快捷模板市场浏览并快速接入常用主流的第三方 MCP 服务（如 MS 魔搭/ModelScope 等），以便降低接入成本并减少手工配置出错。

#### Acceptance Criteria

1. THE 模板市场 SHALL 维护一个内置快捷模板集合，其中每个快捷模板包含模板标识、模板名称、所属分类、简介、文档链接、传输类型、预设连接参数与占位参数定义（每个占位参数含参数名、是否必填及其参数校验规则）。
2. THE 模板市场 SHALL 将快捷模板按分类组织，分类集合至少包含搜索、开发工具、数据库与存储、文件与系统、AI 与模型、办公与协作、自动化与其他。
3. 当管理员按某个分类筛选快捷模板时，THE 模板市场 SHALL 返回该分类下的全部快捷模板。
4. 当管理员按关键字检索快捷模板时，THE 模板市场 SHALL 返回名称或简介中包含该关键字的快捷模板。
5. 如果管理员按关键字或分类检索且不存在匹配的快捷模板，THEN THE 模板市场 SHALL 返回空列表而非错误。
6. 当管理员查看某个快捷模板详情时，THE 模板市场 SHALL 返回该模板的简介、文档链接、传输类型与全部占位参数定义。
7. 当管理员选择某个快捷模板时，THE MCP 连接管理器 SHALL 使用该模板的预设连接参数预填充表单，并将需用户填写的占位参数标记为待输入。
8. WHERE 所选快捷模板要求服务地址与 API Key（例如 MS 服务），THE MCP 连接管理器 SHALL 在管理员填写服务地址与 API Key 之前禁止基于该模板创建上游 MCP 服务。
9. 如果所选快捷模板要求服务地址且管理员填写的服务地址不是合法 URL，THEN THE MCP 连接管理器 SHALL 拒绝创建、保留其他已填写参数并返回指示服务地址格式无效的错误。
10. 如果管理员未提供快捷模板要求的必填占位参数，THEN THE MCP 连接管理器 SHALL 拒绝创建、不持久化任何配置并返回指明缺失参数名称的错误。
11. 当管理员基于快捷模板提交完整参数时，THE MCP 连接管理器 SHALL 按需求 2 与需求 4 对生成的上游 MCP 服务配置执行字段校验。
12. 当管理员基于快捷模板提交的完整参数通过字段校验时，THE MCP 连接管理器 SHALL 按模板生成对应上游 MCP 服务配置并持久化。
13. 当管理员请求查询快捷模板市场且当前不存在任何快捷模板时，THE 模板市场 SHALL 返回空列表而非错误。

### Requirement 15: 小智 AI 远程 MCP 接入点对接

**User Story:** 作为管理员，我希望将聚合后的 MCP 服务接入小智 AI 的远程 MCP 接入点，以便把聚合能力提供给语音终端使用。

#### Acceptance Criteria

1. 当管理员配置小智 MCP 接入点地址并启用小智接入时，THE 小智接入服务 SHALL 通过 WebSocket 连接到该接入点地址。
2. 当小智 MCP 接入点请求工具列表时，THE 小智接入服务 SHALL 返回由聚合服务在应用屏蔽过滤规则与别名/描述重写规则后输出的当前聚合工具集合。
3. 当小智 MCP 接入点请求调用某个存在于当前聚合工具集合中的工具时，THE 小智接入服务 SHALL 将该调用连同原始调用参数路由到聚合服务，并将聚合服务返回的成功结果或错误结果原样返回。
4. 如果与小智 MCP 接入点的 WebSocket 连接建立失败或在运行期间断开，THEN THE 小智接入服务 SHALL 按指数退避策略重连（初始退避间隔默认 1 秒、可配置范围 1 至 60 秒、倍数 2，退避间隔上限默认 60 秒、可配置范围 1 至 3600 秒）。
5. 当管理员停用小智接入时，THE 小智接入服务 SHALL 关闭与小智 MCP 接入点的 WebSocket 连接并停止自动重连，直至管理员再次启用。
6. 如果管理员提交的小智 MCP 接入点地址不是以 ws:// 或 wss:// 为协议前缀的合法 WebSocket URL，THEN THE 小智接入服务 SHALL 拒绝保存、保持当前已持久化配置不变并返回指示地址格式无效的错误。

### Requirement 16: 多维度统计与排行

**User Story:** 作为管理员，我希望查看基于 MCP、工具、API Key 等维度的调用统计与排行，以便了解使用情况并优化配置。

#### Acceptance Criteria

1. 当某个聚合工具被调用时，THE 统计服务 SHALL 记录该次调用的工具标识、所属上游 MCP、所用 API Key、毫秒精度时间戳、响应耗时（毫秒）与执行结果状态（成功或失败）。
2. 当管理员请求查看按上游 MCP 维度的调用统计时，THE 统计服务 SHALL 返回各上游 MCP 在指定时间范围内的调用记录条数（含成功与失败）。
3. 当管理员请求查看按工具维度的排行时，THE 统计服务 SHALL 返回按调用次数降序排列的工具排行，返回条数默认为 10 且可在 1 至 100 范围内配置。
4. 当管理员请求查看按 API Key 维度的调用统计时，THE 统计服务 SHALL 返回各 API Key 在指定时间范围内的调用记录条数（含成功与失败）。
5. WHERE 管理员指定了由开始时间与结束时间构成的统计时间范围，THE 统计服务 SHALL 仅统计该闭区间（含端点）内的调用记录。
6. 如果指定时间范围内不存在调用记录，THEN THE 统计服务 SHALL 返回空统计结果而非错误。
7. 如果管理员指定的统计时间范围的开始时间晚于结束时间，THEN THE 统计服务 SHALL 拒绝该查询并返回指示时间范围无效的校验错误。
8. THE 统计服务 SHALL 以异步方式写入调用统计记录，使工具调用主流程因统计写入而增加的响应耗时不超过 50 毫秒。
9. 如果某次调用统计记录写入失败，THEN THE 统计服务 SHALL 丢弃该次统计记录、不影响工具调用主流程的结果返回且不向调用方返回统计错误。
10. THE 统计服务 SHALL 按配置的统计数据保留期（默认 90 天，可配置范围 1 至 3650 天）保留调用统计记录，并在记录超过保留期后将其清理。

### Requirement 17: 前端管理界面与静态资源代理

**User Story:** 作为管理员，我希望使用现代化响应式管理界面，并由 Go 直接提供前端访问，以便无需 Nginx 即可在手机、平板、PC、宽屏与 4K 大屏上都获得良好的管理体验。

#### Acceptance Criteria

1. THE 静态资源服务 SHALL 由 Go 进程直接对外提供 Vue3 前端静态页面访问而不依赖独立的反向代理。
2. 当浏览器请求前端单页应用的客户端路由路径且该路径不对应任何后端 API 或静态资源文件时，THE 静态资源服务 SHALL 返回前端单页应用入口页面以支持客户端路由。
3. THE 前端管理界面 SHALL 使用响应式布局，并在手机（宽度小于 768 像素）、平板（宽度 768 至 1023 像素）、笔记本/PC（宽度 1024 至 1439 像素）、宽屏（宽度 1440 至 2559 像素）与 4K 超大屏（宽度不小于 2560 像素）五类视口宽度下均完整呈现核心操作入口且无内容溢出。
4. 当未认证用户访问管理界面的受保护页面时，THE 前端管理界面 SHALL 将用户重定向到登录页面。
5. THE 前端管理界面 SHALL 提供上游 MCP 管理、规则管理、API Key 管理、系统设置与统计排行的操作入口。
6. 当后端 API 返回鉴权失败或令牌失效响应时，THE 前端管理界面 SHALL 清除本地会话并将用户重定向到登录页面。
7. WHERE 视口宽度不小于 1440 像素，THE 前端管理界面 SHALL 将主内容区限制在配置的最大宽度内并居中显示，以避免内容在宽屏与 4K 大屏下无限横向拉伸。
8. THE 前端管理界面 SHALL 基于 TailAdmin 模板并使用 Tailwind CSS 工具类构建全部界面，遵循该模板的组件与视觉风格，复杂控件采用 headless 组件结合 Tailwind CSS 实现，且不依赖任何组件式 UI 库。

### Requirement 18: 配置管理（YAML 与环境变量）

**User Story:** 作为管理员，我希望通过环境变量配置数据库与 Redis 连接、通过 YAML 保存常规配置，以便灵活部署与持久化配置。

#### Acceptance Criteria

1. 当系统启动时，THE 配置管理器 SHALL 从环境变量读取 PostgreSQL 连接配置与 Redis 连接配置。
2. 当系统启动时，THE 配置管理器 SHALL 从挂载的 data 目录中的 YAML 文件读取常规配置。
3. 如果必需的环境变量缺失或格式无效，THEN THE 配置管理器 SHALL 在启动日志中记录错误并终止启动。
4. 当管理员在系统设置页面更新常规配置时，THE 配置管理器 SHALL 将更新后的配置写回 YAML 文件并持久化。
5. 如果 YAML 配置文件不存在，THEN THE 配置管理器 SHALL 以默认配置创建该 YAML 文件。
6. 如果 YAML 配置文件内容不是合法的 YAML 格式，THEN THE 配置管理器 SHALL 在启动日志中记录解析错误并终止启动。

### Requirement 19: 敏感凭证加密存储

**User Story:** 作为管理员，我希望存储的 MCP API Key 等敏感凭证被加密保存，以便降低凭证泄露风险。

#### Acceptance Criteria

1. 当系统持久化上游 MCP 的鉴权凭证时，THE 加密服务 SHALL 在写入存储前对该凭证进行加密。
2. 当系统需要使用某个已存储的上游 MCP 鉴权凭证建立连接时，THE 加密服务 SHALL 对该凭证进行解密后使用。
3. THE 网关系统 SHALL 不在管理界面与 API 响应中以明文返回已存储的上游 MCP 鉴权凭证完整内容。
4. 如果加密密钥缺失或无效，THEN THE 加密服务 SHALL 在启动日志中记录错误并终止启动。

### Requirement 20: 连通性启动日志与健康检查

**User Story:** 作为运维人员，我希望在启动日志中清楚看到各依赖与连接的连通性状态，并能查询健康检查，以便快速发现连接问题。

#### Acceptance Criteria

1. 当系统启动时，THE 健康检查服务 SHALL 在启动日志中记录与 PostgreSQL 的连通性结果。
2. 当系统启动时，THE 健康检查服务 SHALL 在启动日志中记录与 Redis 的连通性结果。
3. 当系统启动时，THE 健康检查服务 SHALL 在启动日志中记录每个已启用上游 MCP 服务的连通性结果。
4. 如果某一端依赖或上游 MCP 连接在启动时无法连通，THEN THE 健康检查服务 SHALL 在启动日志中记录该端连接失败及失败原因。
5. WHERE 小智接入处于启用状态，THE 健康检查服务 SHALL 在启动日志中记录与小智 MCP 接入点的连通性结果。
6. 当外部请求访问公开存活探针端点时，THE 健康检查服务 SHALL 仅返回服务自身的存活状态而不返回各依赖与上游 MCP 连接的明细信息。
7. 当请求访问详细健康端点且通过管理员鉴权时，THE 健康检查服务 SHALL 返回系统整体状态及各依赖与上游 MCP 连接的当前健康状态。
8. 如果访问详细健康端点的请求未通过管理员鉴权，THEN THE 健康检查服务 SHALL 拒绝该请求并返回未授权错误。

### Requirement 21: 限流保护

**User Story:** 作为管理员，我希望对外 MCP API 调用具备限流保护，以便防止单个 API Key 过量调用影响系统稳定性。

#### Acceptance Criteria

1. WHERE 某个 API Key 配置了调用速率上限，THE MCP API 服务 SHALL 在每个计数窗口内将该 API Key 的已受理请求数限制在所配置上限内。
2. 如果某个 API Key 在当前计数窗口内的请求数已达到其配置的速率上限，THEN THE MCP API 服务 SHALL 拒绝该 API Key 的后续超额请求并返回限流错误。
3. 当被限流的 API Key 进入下一个计数窗口且其窗口内配额恢复可用时，THE MCP API 服务 SHALL 恢复处理该 API Key 的请求。
4. WHERE 某个 API Key 未配置调用速率上限，THE MCP API 服务 SHALL 不对该 API Key 的请求速率施加限流。

### Requirement 22: 审计日志

**User Story:** 作为管理员，我希望关键管理操作被记录为审计日志，以便追溯配置变更与安全事件。

#### Acceptance Criteria

1. 当管理员登录系统时，THE 审计日志服务 SHALL 记录该登录事件及其时间戳与结果。
2. 当管理员创建、更新或删除上游 MCP 服务、规则或 API Key 时，THE 审计日志服务 SHALL 记录该操作的类型、目标对象与时间戳。
3. 如果某次管理操作因鉴权失败被拒绝，THEN THE 审计日志服务 SHALL 记录该次被拒绝的访问尝试。
4. 当管理员请求查询审计日志时，THE 审计日志服务 SHALL 以分页方式返回按时间倒序排列的审计记录，默认每页 20 条且可在 1 至 200 范围内配置每页条数。
5. THE 审计日志服务 SHALL 按配置的审计日志保留期（默认 180 天，可配置范围 1 至 3650 天）保留审计记录，并在记录超过保留期后将其清理。

### Requirement 23: 数据持久化与备份

**User Story:** 作为运维人员，我希望系统数据可持久化并可备份恢复，以便在容器重建或故障时不丢失配置数据。

#### Acceptance Criteria

1. THE 网关系统 SHALL 将 YAML 配置文件与本地持久化数据存储在挂载的 data 目录中。
2. 当容器重建并重新挂载同一 data 目录时，THE 配置管理器 SHALL 从该目录恢复先前持久化的 YAML 配置。
3. THE 网关系统 SHALL 将业务数据（上游 MCP 配置、规则、API Key 元数据与统计记录）持久化到 PostgreSQL 数据库。
4. 当管理员请求导出系统配置时，THE 配置管理器 SHALL 生成包含当前配置的可导入备份文件。
5. 当管理员导入合法的配置备份文件时，THE 配置管理器 SHALL 校验并应用该备份中的配置。
6. 如果导入的配置备份文件格式无效或校验失败，THEN THE 配置管理器 SHALL 拒绝导入并返回备份文件无效错误。

### Requirement 24: Docker 部署与 CI/CD

**User Story:** 作为运维人员，我希望系统支持 Docker 容器一键部署并通过 GitHub Action 自动发布镜像，以便简化部署与发布流程。

#### Acceptance Criteria

1. THE 网关系统 SHALL 提供将 Go 后端与 Vue3 前端打包为单一可运行 Docker 镜像的容器化构建定义。
2. 当容器以配置好的环境变量与挂载的 data 目录启动时，THE 网关系统 SHALL 完成初始化并对外提供管理界面与 MCP API 服务。
3. 当代码变更被推送到配置的发布触发条件时，THE GitHub Action SHALL 自动构建 Docker 镜像。
4. 当 Docker 镜像构建成功时，THE GitHub Action SHALL 将该镜像发布到配置的远程镜像仓库。
5. 如果 Docker 镜像构建或发布过程失败，THEN THE GitHub Action SHALL 将该工作流标记为失败并记录失败原因。

### Requirement 25: 工程化与代码质量规范

**User Story:** 作为开发者，我希望前端基于成熟模板、后端使用官方工具链初始化，并接入统一的代码质量工具，以便保持一致的代码风格、降低维护成本并减少风格争议。

#### Acceptance Criteria

1. THE 前端工程 SHALL 基于 TailAdmin Vue 模板（vue-tailwind-admin-dashboard）初始化（克隆模板并在其上适配改造），复用该模板已提供的 Vite + TypeScript + Tailwind CSS 与基础布局，而非从零手工创建工程目录与配置文件。
2. THE 后端工程 SHALL 使用 Go 官方工具链（`go mod init`）初始化模块，而非手工拼凑模块定义。
3. THE 前端工程 SHALL 集成 ESLint 并提供可执行的 lint 校验命令。
4. THE 前端工程 SHALL 集成 Prettier 并提供可执行的格式化命令，且 Prettier SHALL 对 Tailwind CSS 工具类进行一致的格式化排序，同时 ESLint 与 Prettier 的规则不产生相互冲突。
5. 如果前端代码存在违反已配置 ESLint 规则的问题，THEN THE 前端 lint 校验命令 SHALL 以非零退出码报告该问题。
6. THE 后端工程 SHALL 通过 `gofmt`（或 `goimports`）统一 Go 代码格式。
7. THE 前端工程 SHALL 以 Tailwind CSS 作为样式系统，界面样式遵循 TailAdmin 模板的视觉风格。
